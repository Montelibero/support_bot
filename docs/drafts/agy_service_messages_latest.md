### Принятые риски (Accepted Risks)

1. **Отсутствие бэкфилла истории:** Сообщения бота, отправленные до деплоя новой таблицы, отсутствуют в `t_service_messages`; при ответе оператора на них будет выводиться стандартная подсказка о потере истории переписки, пока они не уйдут из контекста активной работы.
2. **Ретеншн на старте сервиса:** Удаление записей старше 90 дней выполняется однократно при запуске в `update_db()`.
3. **Синхронная запись в БД внутри middleware:** Запись в SQLite выполняется синхронно в цепочке запроса (<1 мс), исключая гонку «оператор ответил быстрее, чем завершилась фоновая запись».
4. **Уведомления об ошибках через очередь:** При сбоях через `DeliveryQueue` ошибки пишутся в `delivery_jobs.error` и не отправляются в мастер-чат, поэтому регистрировать в реестре нечего. Прямые сбои синхронной доставки регистрируются через `registration_enabled`.
5. **Отсутствие индекса по `record_add_date`:** Retention-запрос `DELETE` выполняет сканирование таблицы только при старте, что оправдано отсутствием накладных расходов на поддержание индекса при каждом `INSERT`.
